# 碰爪 · 项目总览

更新：2026-09-05。已确定方向来自本次产品要求；实现事实见[现状台账](00-current-state.md)。

## 定位与价值

碰爪以宠物为中心，让大城市宠物主人找到合适的公共遛宠地点，在真实出门中认识宠物伙伴，经过双方确认后保持联系。可以约下次一起遛，也可以看见好友本次主动共享的公共地点，自主决定前往。

价值依次是：减少找地点和确认准入规则的成本；用宠物身份和散步习惯帮助判断是否适合认识；让联系和位置暴露由用户主动决定；把真实陪伴留在私人日历。

## 用户与痛点

| 用户/场景 | 困难 | 产品回应 |
| --- | --- | --- |
| 刚搬家或路线单一的城市主人 | 普通地图不说明可携宠区域、入口和限制 | 有来源的精选地点和可核实规则 |
| 不爱主动聊天的主人 | 开口和约人有压力 | 先名片，可不写申请介绍；好友后自主前往公共地点 |
| 慢热宠物照护者 | 热闹场地和直接凑近不一定合适 | 环境/牵引/性格资料；安静筛选待补 |
| 已认识的宠物伙伴 | 想再见又不想持续暴露行踪 | 单次邀请、主动共享、随时隐身、到期关闭 |
| 记录陪伴的主人 | 照片、照护记录分散 | 私人日历关联遛弯及手工确认相遇 |

这些是目标人群和产品假设，不是已完成访谈结论。真人测试需验证地点是否足够近、申请是否易理解、少聊天是否更自在，不以信息流停留时长衡量价值。

## 核心闭环

不知道去哪 → 找到有资料的公共地点 → 看入口和当日要求 → 出门 → 从帖子/名片/扫码认识宠物 → 申请好友 → 对方接受 → 约下次或看对方本次主动共享地点 → 手动记录真实相遇 → 再次出门。

独自出门也有价值。好友共享不生成邀请、到场通知或见面义务。发帖是辅助入口；照护和回忆不要求公开。

## 典型场景

1. 只想找地方：看北京精选、核对专区和牵绳要求，收藏出门；拒绝定位仍可看资料和手动搜索。
2. 线下已经遇见：扫碰爪码先开名片，申请后等确认；当前真实跨账号流程未完成。
3. 不想先聊天：看好友主动共享的公共地点，自主决定去不去；好友结束或隐身后不再显示。
4. 提前约定：选好友、未来时间和地点，等待回应；取消同步到会话和日历；到时不推定到场。
5. 今天结束：先停共享，再选填照片、我/TA心情、文字和真正遇到的伙伴，保存私人日历。

## 非目标

- 不以内容消费、网红、粉丝排行、积分商城或AI电子宠物为主线。
- 不做陌生即时私聊、随机匿名匹配、自动加好友、自动发布位置和持续精确行踪展示。
- 不把同地标记当作相遇，不把接受邀请当作参加证明。
- 首批不承诺全国地点、全宠种准入、代遛/寄养交易、医疗诊断或活动组织服务。
- 多宠物、家庭照护、陌生申请开关、正式导航等选择进入[决策表](08-roadmap-decisions.md)。

## 建议的验证标准

观察用户能否独立选出适合地点、理解资料尚未实勘、区分好友/聊天/共享三种权限、不依赖私聊安排再见，以及结束后知道他人看不到地点。记录测试参与者任务成功与困惑原因，不预设增长率和商业化目标。
