## 文档与素材

本目录提供可随代码维护的 Markdown 文档及 37 张产品演示原图。私人飞书链接和同步记录不随开源仓库发布；相关原始资料保留在作者本机备份中。

文档中的历史核查记录仅说明对应版本的事实，不代表真实多人服务已经实现或本次新增测试已经通过。

## 统一约定

- **事实**：本次源码核查、历史测试记录或有来源的公开材料，标清证据类别和范围。
- **建议**：推荐方案尚未批准，不能直接当作开发承诺。**待确认**：选择改变权限、模型或范围，统一进入D-xx决策表。
- 实现状态：**已实现**＝明确范围的真实本机能力；**演示模拟**＝本机社交/持久化行为；**待开发**＝方向已确定但能力缺失；**待确认**＝机制/范围未定。实现状态不等于测试通过。
- 优先级均为建议：**P0**＝真实多人内测闭环、权限或数据阻断；**P1**＝首发体验和上线准备；**P2**＝可延后扩展。不暗含人力或工期。
- 需求编号 `PZ-模块-序号`；业务规则 `BR-xx`；决策 `D-xx`；历史测试 `T01–T45`；新设计测试 `AT-xx`。编号稳定，废弃保留说明。
- 用户＝登录的人；宠物＝其管理的宠物档案；好友＝双方确认的宠物关系（真实账号层级待D-01）；地点共享＝本次遛弯主动共享公共地点，不等同于公开帖子、系统定位授权或好友关系。
- 隐身＝停止向好友展示本次地点；结束＝终止遛弯并保留私人记录；已到约定时间≠已完成≠已相遇。

## 维护方式

实现变化先更新00证据，再更新03状态及04–07，最后调整08门槛。产品决定记录决定人、日期和批准内容后再改规则；未答复仍待确认。新测试必须记录版本、环境、账号、步骤、实际结果和证据，不复制旧通过到新版本。商店提交前重新查阅公开规则。
